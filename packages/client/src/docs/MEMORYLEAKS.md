ОТЧЁТ ОБ ОБНАРУЖЕНИИ И УСТРАНЕНИИ УТЕЧКИ ПАМЯТИ

Введение
В процессе разработки игрового приложения на React была обнаружена проблема: при переключении страниц и повторном запуске игры увеличивался объём удерживаемой памяти. Поведение указывало на утечки памяти, связанные с несвоевременной очисткой ресурсов и неосвобождёнными ссылками. Цель работы — найти источники утечки, описать причины и выполнить корректные правки.

Симптомы утечки
Рост вкладки Retained memory в React DevTools. Постепенное увеличение задержек после нескольких запусков игры. Компоненты оставались в памяти даже после размонтирования.

Анализ и причины утечки В проекте утечка была найдена в пользовательском хуке useGameLogic, а также в компоненте GetStartPage.
3.1 Утечка №1 — неочищенный setTimeout в handleCardClick setTimeout(() => { setFlipped([]) setDisabled(false) }, 1000)

Почему это утечка?

setTimeout не находится внутри useEffect, поэтому React не может автоматически его очистить при размонтировании компонента.
Если пользователь быстро покидает страницу — таймер всё равно выполнится.
Его callback удерживает:
старые значения состояния,
ссылку на компонент,
замыкание handleCardClick. Это создаёт зависшую ссылку в памяти, которую GC не может освободить.
3.2. Утечка №2 — эффект в GetStartPage имеет неполные зависимости Исходный код: useEffect(() => { ... }, [timer]) Но внутри используются: navigate getStart Это сохраняет старые замыкания в памяти, создавая кэширование неактуальных ссылок.

Устранение утечек 4.1 Исправление setTimeout в useGameLogic Было (утечка): setTimeout(() => { setFlipped([]) setDisabled(false) }, 1000)
Стало (исправлено): const timeoutRef = useRef<NodeJS.Timeout | null>(null)

useEffect(() => { return () => { if (timeoutRef.current) clearTimeout(timeoutRef.current) } }, [])

timeoutRef.current = setTimeout(() => { setFlipped([]) setDisabled(false) }, 1000)

Таймер корректно очищается
Стейт не обновляется после размонтирования
Замыкание больше не удерживается в памяти
4.2 Исправление GetStartPage useEffect Было: useEffect(() => { ... }, [timer])

Стало: useEffect(() => { if (timer === null || timer === 0) return

const countdown = setTimeout(() => setTimer(timer - 1), 1000)

if (timer === 1) { getStart?.() navigate(ROUTES.gamePage) }

return () => clearTimeout(countdown) }, [timer, getStart, navigate])

Эффект больше не удерживает старые значения функций
Замыкание стабилизировано
Результаты после исправления После внесения изменений было проверено поведение приложения: Уменьшилось количество удерживаемой памяти (Retained memory). Не появляется предупреждений о попытке обновить размонтированный компонент. Поведение стало стабильным при многократном переходе между страницами. Компоненты корректно уничтожаются при navigate().

Заключение В проекте была выявлена утечка памяти, связанная с неочищаемым setTimeout и нестабильными замыканиями. После внедрения очистки таймеров и корректировки зависимостей хуков память перестала расти, а приложение работает стабильно. Все исправления протестированы и успешно внедрены.
